# Яцзы (Yatzy)

Консольная игра в кости Яцзы на C++17. Используется только стандартная библиотека (STL).
Проектная работа команды из трёх человек, НИУ ВШЭ.

## Правила

- 5 кубиков, 13 раундов. В каждом раунде до 3 бросков; между бросками можно отложить любые кубики.
- После бросков игрок обязан записать результат в одну свободную графу. Если комбинация не подходит — записывается 0.
- В каждой графе может быть только одно значение.

| Графа | Условие | Очки |
|---|---|---|
| Единицы … Шестёрки | — | Сумма кубиков с этим значением |
| Тройка | 3 одинаковых | Сумма всех кубиков |
| Каре | 4 одинаковых | Сумма всех кубиков |
| Фул-хаус | 3 одного значения + 2 другого | 25 |
| Малый стрит | 4 значения подряд | 30 |
| Большой стрит | 5 значений подряд | 40 |
| Яцзы | 5 одинаковых | 50 |
| Шанс | Любые кубики | Сумма всех кубиков |

**Решения команды:**

- Бонус верхней части **+35** начисляется, если сумма верхней части **63 и больше**.
- Яцзы не считается фул-хаусом (по правилам нужны два разных значения).
- Побеждает игрок с наибольшим итогом; при равенстве — ничья.

## Сборка

Нужны CMake 3.16+ и компилятор с C++17: MSVC (Visual Studio 2019+), clang (Xcode) или g++/MinGW.

**Visual Studio / CLion / VS Code с CMake Tools:** открыть папку проекта — CMakeLists.txt подхватится сам. Запускать цель `yatzy`.

## Как добавить модуль в сборку

1. Создать `include/ИмяМодуля.h` и `src/ИмяМодуля.cpp`.
2. Добавить `src/ИмяМодуля.cpp` в список `add_library(yatzy_core ...)` в CMakeLists.txt
   (если блок ещё закомментирован — раскомментировать).
3. `main.cpp` в `yatzy_core` не добавлять — он только в `add_executable(yatzy ...)`.
4. Пересобрать: `cmake -S . -B build && cmake --build build` — должно быть 0 предупреждений.
5. Коммит `.h`, `.cpp` и CMakeLists.txt — одним pull request, чтобы у остальных сборка не сломалась.

## Как проверять функции (тесты)

- Тесты лежат в `tests/`, по файлу на модуль: `tests/ИмяМодуляTests.cpp`.
- Тест — обычная программа с `main`: вызывает функции и сравнивает результат с ожидаемым.
  Не использовать `assert` — в Release он отключается. Программа возвращает 0, если всё прошло, и 1, если нет.
- Новый файл тестов добавить в CMakeLists.txt:
  ```cmake
  add_executable(имя_tests tests/ИмяМодуляTests.cpp)
  target_link_libraries(имя_tests PRIVATE yatzy_core)
  yatzy_set_warnings(имя_tests)
  add_test(NAME имя COMMAND имя_tests)
  ```
- Запуск всех тестов: `ctest --test-dir build -C Debug --output-on-failure`.
- Что обязательно покрыть тестами: подсчёт очков по всем 13 графам, стриты в любом порядке кубиков,
  бонус ровно при 63, запись в занятую графу, итоговую сумму.
- Когда тесты подсчёта начнут проходить — удалить `continue-on-error: true` в `.github/workflows/build.yml`.

**Терминал (Mac и Windows):**

```bash
cmake -S . -B build
cmake --build build
./build/yatzy                 # Mac
build\Debug\yatzy.exe         # Windows (Visual Studio)
```

**Тесты:**

```bash
./build/yatzy_tests           # или: ctest --test-dir build -C Debug
```

На Windows игру лучше запускать в **Windows Terminal** — там корректно работают кириллица и цвета.

## Управление

На любом шаге можно ввести:

- `выход` — выйти из игры.

## Договорённости

**Имена:** типы — `PascalCase`, функции и переменные — `camelCase`, поля класса — `m_camelCase`, константы — `UPPER_CASE`. Однобуквенные имена — только для счётчиков циклов.

**Методы:** один метод — одно действие. Метод длиннее ~30 строк стоит разбить.

**Комментарии:** перед каждым классом и методом в `.h` — что делает, что принимает и возвращает (`///`). Сложные места в `.cpp` — отдельный комментарий.

**Предупреждения:** перед коммитом проект собирается без предупреждений (флаги `-Wall -Wextra -Wpedantic -Wconversion` / `/W4` уже включены в CMake). GitHub Actions собирает проект на Windows и macOS с предупреждениями-как-ошибками.

**Запрещено:** сторонние библиотеки; `conio.h`, `_getch`, `system("cls")`, `system("pause")`; `rand()`; функции из C (`strcpy`, `fopen`, `sprintf`); код под конкретную ОС вне `Console.cpp`.

**Кодировка:** все файлы в UTF-8, окончания строк LF (настроено в `.editorconfig` и `.gitattributes`).
